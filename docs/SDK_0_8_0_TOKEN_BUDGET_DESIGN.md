# 0.8.0 token 预算：实现边界与验证要求

状态：源码已部分接入，尚无当前安装包的真实 OpenCode 验收，不构成 G15 通过证据。保持现有 Goal 的默认 `budget.tokens: null`，不删除可配置 token 上限的范围。

## 当前实际调用链

当前源码允许 SDK 自有 OpenCode 适配器在宿主提供版本化计量合同后接入非空 token 上限。模型目录 `token_budget.request_limit` 是宿主承诺的单次总计费上界，`output_limit` 限制输出；SDK 不会从字符数推导输入上界，也不能代替宿主验证提供方承诺。主模型及所有回退模型均须配置合同。

代理在发送前以模型请求身份调用 `ApplicationBudget.reserve_group`，覆盖所有有限额祖先；完整成功响应才调用 `settle_group`。支持 Chat Completions 与 Anthropic Messages 用量解析；token 计量模式下 Responses 路径尚不支持。HTTP 长度或分块结束未确认、提供方错误、用量缺失或矛盾均保留未知预留。非流式用量还必须位于所支持的成功响应格式内，不能仅凭 `usage` 字段结算。

当前分组账本默认仍拒绝 pending 预留；token 代理显式启用 `allow_pending`，只将经过完整组身份与金额核对的分组预留按其完整上界计入容量。旧单范围 pending 或任何 unknown 仍阻止准入。并发准入须满足各祖先的已用量与全部预留上界之和不超过额度。缺少可信合同的模型继续拒绝启动。上述均为实现边界，不是 G15 验收结论。

OpenAI 兼容流式解析另要求同一非空响应 ID、单一 index-0 结果的明确结束，以及最终用量；允许结束后的空 choices 用量分块。只有用量和 DONE、缺失/混合响应 ID 或没有结束结果时保持未知。仅工具调用及空文本完成不被误拒。此修复尚待当前安装包验收。协议依据：[Chat Completions streaming events](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。

## 必须保持的行为

1. 提供方请求发送前，应用及完整逻辑祖先链须原子预留该请求的可信 token 上界；不足或未知则不发送。仅在请求结束后累计 usage 不能保证预算上限。
2. 一个不可变请求身份只获得一次发送授权。身份包括调用、执行代次和模型请求序号；重开或回执丢失不能再次发送。重试、子调用和 goal 轮次均沿用原预算与期限。
3. 上界不能来自模型自报、字符数猜测或未验证的 tokenizer。实现需有宿主授权、版本固定的模型计量合同，覆盖输入、输出、推理以及缓存 token 的计费定义，并限制实际发送的输出参数。无法得到可信上界的模型保持明确拒绝，不伪装为已支持。
4. 成功结束且提供方给出完整、合法、相互一致的用量事实后，才可将同一预留按实际用量结算；缺失、截断、格式错误、冲突、超界或发送结果不明，保留未知预留，阻止后续消费，不能释放为零。HTTP 错误本身不证明未计费。
5. 流式解析须有字节和事件数量上限，并正确处理任意分块、UTF-8 边界、重复 usage、最终结束事件以及客户端提前断开。不能为收集统计而重放请求。重开只消费已有事实。
6. 没有 token 配额的旧调用保持原行为。双语 Wiki 明确默认值、支持的计量合同、未知处理和宿主解除条件；不能把 capability 声明本身作为执行证据。

## 接入与验收顺序

先固定提供方计量合同及两种协议的用量格式，再把预留／结算接入现有代理资源生命周期。沿用预算分组接口，不另造逐祖先扣费或释放路径，不直接修改 SDK 数据库。

本地验证覆盖多祖先不足时零发送、并发争抢、请求身份重放、流式任意分块和截断、超界未知、发送后中断、预留／结算提交前后崩溃，以及重开后不重复发送。合成提供方用于这些故障检查，不能代替 G15 实际 OpenCode 验收。

最终须用同一安装包通过真实 OpenCode 请求验证提供方 usage、原子预算与下游消费：足额调用成功，实际用量一致；不足请求在到达提供方前被拒绝；重开不增加请求且未知预留不被自动清除。当前这些证据均尚缺，不能解除 G15 未完成状态。
