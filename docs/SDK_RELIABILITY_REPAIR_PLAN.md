## 依据与边界

9 月 16–18 日下游记录显示：已提交 checkpoint 后停机超时；身份预检读取大历史库；
跨段结果缺少原任务描述；调用方结束后出现迟到结果。停机具体卡点未复现，不能定性为死锁。
约 51 GiB 临时备份是下游探测脚本事件，不归因为身份检查。

本轮保留当前开发树已有存储改动，不发布、不操作 ModPort 历史库，不自动迁移。
SDK 提供事实与持久化原语；返工资格、业务验收、模型是否理解结果由应用决定。

## 实施顺序及验收

1. **停机诊断（优先）**：复用 Host health/error，记录各收尾阶段及耗时、未完成阶段、
   worker 状态和继续等待提示。异常后可读取结构化报告，保留 `True`、`TimeoutError`
   和清理错误原有契约。未经观察的待投递数量和持久化状态明确为未知；报告生成不能
   在超时后扫描或等待业务库。覆盖 worker/通知回调/资源关闭阻塞、同时阻塞和再次停止。
   同步第三方调用采用协作式停止，不承诺强制中断。
2. **检查分级（优先）**：模块身份、schema、绑定、完整性检查区分成本和结论。
   保持旧默认语义，提供明确的轻量入口与扫描预算、进度和实际检查范围。
   未检查、不完整、损坏分开；预算中断不得变成损坏或兼容成功。
   审计 `quick_check`、绑定遍历、历史计数、schema validator 和 `dbstat` 隐式扫描。
   SQL trace 验证轻量路径，大库/中断夹具验证预算，完整检查保留损坏与绑定不符负例。
3. **有界来源查询**：公开按 execution/result 身份定位指定库内原 Run/task/attempt、
   冻结命令绑定和前后段来源；使用索引点查，限制载荷及时间，明确缺失/不完整。
   支持当前 schema 3 内容编码，不加载完整 Run，不扫描目录，不推断未登记部署资料。
   多库来源认证和冷归档自动解析继续归属存储生命周期计划，不暗示已完成。
4. **调用方接收确认**：复用 `NotificationInbox` 的持久化、去重和冲突检查，提供
   稳定 source/caller/request 到结果的关联、迟到结果点查、传输报告与调用方显式确认。
   结果可用、传输报告、调用方确认分别记录；读取和发送不隐式确认。
   不修改 MCP 业务策略，不用确认推导理解或审查通过。验证重启、迟到结果、响应丢失重试、
   身份冲突、不同调用方隔离、确认内容不匹配及并发。
