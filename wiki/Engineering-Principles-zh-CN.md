# 接入工程原则

[English](Engineering-Principles.md) | [简体中文](Engineering-Principles-zh-CN.md) | [首页](Home-zh-CN.md)

这些原则用于提高持久化 SDK 接入的可运维性和可审查性。
它们约束应用的工程流程；SDK 仍负责执行、存储、租约和投递，
应用负责业务含义和产品验收。完整定义和检查项见[详细指南](../docs/INTEGRATION_PRINCIPLES.md)。

| 原则 | 做法 |
| --- | --- |
| 版本向量 | 分开记录发行版本、实际导入模块、契约和存储 schema、registry 与部署身份。 |
| 受监督的生命周期 | 记录所有者、心跳、队列进度和停止结果；PID 存在不等于服务健康。 |
| 审查身份 | 分开报告结构可复用、独立审查、本 Run 验证和发布批准。 |
| 证据闭环 | 新来源或日志只是证据，不会自动关闭问题；先定义闭环条件，再独立评估。 |
| 知识与验证 | 只有当前必须的知识阻塞受影响工作；实现后的检查带到声明的验收关卡。 |
| 因果诊断 | 对比精确执行身份、首个致命条件、生命周期里程碑和认证测试覆盖。 |
| 证据阶梯 | 明确是 fixture、SDK 集成、重启、模型、构建、运行时还是产品验收证据。 |
| 冻结候选 | 最终审查和全量验证前冻结代码、依赖、registry 和规则。 |
| 安全发现 | 变更持久化对象前先定位并匹配；存在歧义时不能创建新 lineage。 |

## 开始工作前

写下问题、验收条件、候选身份以及能够回答问题的证据等级。
为活动中的持久化工作保留匹配的部署。复用数据库前阅读[存储与升级](../docs/STORAGE_AND_UPGRADES.md)，
重试中断的 Effect 前阅读[恢复指南](../docs/SDK_RECOVERY.md)。

## 报告成功前

保留首个失败和解释它的原始证据，明确列出跳过的测试和未验证能力。
如果候选、依赖、生成产物或验收规则发生变化，就重新执行最终检查。
绿色测试数量、稳定摘要或 Agent 自报只能证明其背后实际完成的证据等级。

编程 Agent 请使用[验证检查清单](../DocsforAgents/VERIFICATION.md)。
